Berikut adalah skenario pengujian yang bisa Anda jalankan untuk memverifikasi bahwa checklist progress bertahan dengan benar setelah refresh:

### **Skenario 1: Happy Path — Progress Bertahan**

| # | Langkah | Ekspektasi |

### **Skenario 2: Isolasi Data — Progress Tidak Bocor Antar Metode**

| 2.1 | Buka Metode A, centang step 1 dan 2 | Step 1 dan 2 checked di Metode A |

| 2.3 | Centang step 3 di Metode B | Hanya step 3 checked di Metode B |
| 2.4 | Kembali ke Metode A | Step 1 dan 2 **masih checked** di Metode A |
| 2.5 | Refresh halaman saat di Metode A | Step 1 dan 2 **tetap checked** |

### **Skenario 3: Reset Berfungsi dengan Benar**

| # | Langkah | Ekspektasi |
|:---|:---|:---|

| 3.2 | Klik tombol "Reset" | Semua step kembali **unchecked** |

### **Skenario 4: Edge Cases — Ketahanan terhadap Error**

| # | Langkah | Ekspektasi |
|:---|:---|:---|
| 4.1 | Buka DevTools → Application → LocalStorage → Hapus key checklist secara manual | Aplikasi **tidak crash**, checklist muncul dengan semua step unchecked (graceful fallback) |
| 4.2 | Buka DevTools → Ubah nilai key checklist menjadi string JSON yang tidak valid (misal: `{broken`) → Refresh | Aplikasi **tidak crash**, checklist muncul dengan semua step unchecked (graceful fallback dari JSON parse error) |
| 4.3 | Buka DevTools → Ubah nilai key checklist menjadi tipe data yang salah (misal: angka `123`) → Refresh | Aplikasi **tidak crash**, graceful fallback |
| 4.4 | Buka dua tab browser dengan metode yang sama → Centang step berbeda di masing-masing tab → Refresh salah satu tab | Tab yang di-refresh menampilkan progress yang tersimpan di localStorage (tab terakhir yang menulis menang) — **tidak ada error** |

## 🛡️ Prinsip Defensive Design yang Relevan

Untuk memastikan checklist tidak pernah gagal secara silent, implementasi idealnya memiliki:

1. **Try-catch pada read/write localStorage** — jika `JSON.parse()` gagal, fallback ke state kosong
2. **Validasi tipe data** setelah parse — pastikan hasilnya adalah object/array yang diharapkan
3. **Key namespacing** — gunakan prefix seperti `gustafta_checklist_{methodId}` untuk mencegah key collision
4. **SSR safety** — jika menggunakan Next.js, pastikan `localStorage` hanya diakses di client-side (setelah mount)
