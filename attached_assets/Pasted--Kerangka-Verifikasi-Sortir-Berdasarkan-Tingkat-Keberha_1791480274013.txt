# 📋 Kerangka Verifikasi: Sortir Berdasarkan Tingkat Keberhasilan

Saya memahami kekhawatiran Anda: jika mekanisme fallback 101% gagal, pertanyaan tanpa data percobaan akan muncul di **puncak** daftar "tersulit" — ini adalah risiko misinformasi yang serius bagi admin.

Berikut adalah skenario verifikasi untuk memastikan perilaku sortir bekerja dengan benar dan mengidentifikasi titik kegagalan potensial.

---

## ⚠️ Titik Kegagalan Potensial (Risk Analysis)

Berdasarkan kekhawatiran Anda, berikut adalah skenario di mana mekanisme 101% bisa gagal:

### **Risiko 1: Logika Fallback Tidak Dieksekusi**

**Penyebab Potensial:**
- Kondisi `if (attempts === 0)` tidak terpicu karena tipe data salah (misal: `attempts` adalah string `"0"` bukan angka `0`)
- Logika fallback berada di luar scope yang tepat
- Race condition: data dimuat setelah sortir dieksekusi

**Indikator Kegagalan:**
- Pertanyaan tanpa data muncul di **puncak** daftar
- Tingkat keberhasilan ditampilkan sebagai `0%` atau `NaN%` alih-alih `101%`

**Cara Verifikasi:**
- [ ] Periksa console browser untuk error JavaScript
- [ ] Inspeksi nilai `rate` di DevTools → apakah benar-benar 101 untuk pertanyaan tanpa data?

---

### **Risiko 2: Sortir Ascending vs Descending Tidak Konsisten**

**Penyebab Potensial:**
- Logika fallback 101% dirancang untuk sortir **ascending** (tersulit di atas)
- Ketika admin memilih sortir **descending** (termudah di atas), 101% justru membuat pertanyaan tanpa data muncul di **puncak**

**Ekspektasi yang Benar:**
- **Ascending** (tersulit → termudah): Pertanyaan tanpa data di **bawah**
- **Descending** (termudah → tersulit): Pertanyaan tanpa data di **atas** (karena 101% > semua nilai nyata)

**Cara Verifikasi:**
- [ ] Toggle sortir ascending → pertanyaan tanpa data di bawah ✅
- [ ] Toggle sortir descending → pertanyaan tanpa data di atas ✅ (ini benar, karena 101% adalah "paling mudah")

---

### **Risiko 3: Nilai 101% Bocor ke UI**

**Penyebab Potensial:**
- Nilai sintetis 101% ditampilkan langsung ke admin alih-alih diganti dengan label "Belum ada data"

**Ekspektasi yang Benar:**
- Di tabel: kolom "Tingkat Keberhasilan" menampilkan **"Belum ada data"** atau **"N/A"**, bukan "101%"
- Nilai 101% hanya digunakan secara internal untuk sortir

**Cara Verifikasi:**
- [ ] Periksa tampilan UI: apakah admin melihat "101%" atau "Belum ada data"?
- [ ] Jika melihat "101%", ini adalah bug UI (nilai internal bocor)

## 🛡️ Prinsip Defensive Design yang Relevan

Task ini mencerminkan prinsip penting:

1. **Explicit Over Implicit**: Nilai sintetis 101% adalah eksplisit, bukan mengandalkan perilaku default sortir
2. **Fail-Safe by Default**: Jika fallback gagal, sistem harus tetap menampilkan pertanyaan tanpa data di posisi yang tidak menyesatkan
3. **Separation of Concerns**: Nilai internal (101%) tidak boleh bocor ke UI — admin hanya melihat "Belum ada data"

## 💡 Pertanyaan untuk Anda

Untuk memastikan verifikasi berjalan efektif:

1. **Apakah Anda sudah memiliki data uji** yang mencakup pertanyaan dengan dan tanpa data percobaan?

2. **Apakah Anda ingin saya buatkan matriks ekspektasi lengkap** untuk semua kombinasi sortir (ascending/descending) × status data (ada/tidak ada)?

3. **Apakah ada edge case lain** yang menurut Anda perlu diuji (misal: pertanyaan dengan 1 percobaan dan 0% keberhasilan vs pertanyaan tanpa data)?

Silakan jalankan verifikasi sesuai waktu Anda. Jika Anda menemukan anomali (terutama jika pertanyaan tanpa data muncul di puncak daftar "tersulit"), beri tahu saya detailnya, dan kita akan analisis dampaknya bersama. 🚀
